# 拿到一张掩版：先选路，再动手（agent 方法论）

"这块要重绘/要打码，掩版从哪来？" —— 有五条路，**机制、代价、可靠性差别很大**。默认**不是**最贵的、
也不是最省的：先回答下面四个问题，再按表选路。

## 0. 先回答四个问题

| 问题 | 它决定什么 |
|---|---|
| **目标是什么形状？** 圆/方/规整（苹果、球、头、道具）还是不规则/细长（绳子、发丝、手指） | 规整 ⇒ 路 3（网格 + 矩形/内接椭圆）就够；不规则 ⇒ 路 1/4/5 |
| **目标被遮挡吗？** （手指压着话筒、绳子绕在身上、道具在身前） | 有遮挡 ⇒ 掩版必须是 **`物体 − 遮挡物`**，光有外接框一定把手一起重绘掉 |
| **周围环境复杂吗？目标突不突出？** | 周围简单 + 目标颜色突出 ⇒ 路 5（colorblock）几条命令搞定；反之走 1/2/4 |
| **图能上传云端吗？**（内容合规 + 有预算） | 能 ⇒ 路 2 上限最高（语义身份最清楚）；不能 ⇒ 1/3/4/5 都是纯本机 |

## 1. 五条路

| # | 路子 | 机制 | 代价 | 可靠性 | 什么时候用 |
|---|---|---|---|---|---|
| 1 | **检测框 / 骨架** | 本机 `libs/anime-detection`：人/头/手/脚 + 面部四类给框；**骨架膨胀**给人体、**头框内接椭圆**给头 | 免费、本机、几秒 | **高**（头框尤其准；骨架已到可用） | 默认首选：部件重绘（手/脚/脸/眼/嘴）、整人、单肢体 |
| 1b | **SAM（提示式分割）** | 本机 SAM ViT-B（`models/sams/`，375 MB）：给**框 / 正点 / 负点**，它返回贴真实分界的掩版（可多提议） | 免费、本机、**1~2 秒** | 中高：边界比框准得多；但它**不懂语义**（"脸"给的是"皮肤"），要靠提示与后处理补 | 目标边界靠**纹理/形状**而不是颜色时（脸、手、不规则道具）、以及给色块法做"这条边到底在哪"的裁判 |
| 2 | **云端视觉模型分色** | 只把**切片**交给云端图像模型（如 DashScope `wan2.7-image`）："A 涂红、B 涂蓝、背景涂黑" → 阈值转掩版 | **要钱**（¥0.1/次起）、~10 秒、要联网、**要过合规** | **高** —— "直逼人 PS 画出来的质量"；语义身份最清楚 | 两人贴在一起/互相遮挡、要按"是谁"分；抠图去背景 |
| 3 | **网格数格子 → 矩形/内接椭圆** | 叠网格（`tools/crop_view.py --grid`，标注**原图坐标**），agent 数格子读出大致范围，再用矩形或**内接椭圆** | 免费、秒级 | 中（范围是读出来的，边界不贴形状） | 圆/方规整物体（苹果、球、道具、头）；也当前面任何一条路的**前置定位** |
| 4 | **切片 + colorblock 加减法** | 先切片放大，再用 `colorblock.py --mode compete`：ROI 框定 + **确定负样本**（背景/白布）参与竞争，各类掩版做加减 | 免费、本机、**秒级可迭代** | 中高（取决于目标是否突出、节点是否够细） | **周围简单 + 目标突出**（话筒、绳子、纯色道具）；需要"物体−遮挡物"时 |
| 5 | **画布让人涂** | `human_canvas`：人涂多层（要改的/要保留的）+ 矢量点 | **要人**、非阻塞（打开 → 让出回合 → 读回） | **最高** | 前四条互相矛盾、边界是"判断"而非"测量"、错了代价很大 |

> **这五条不是互斥的，是零件**：任何一条路的掩版都能进"加减法"——检测框/内接椭圆给"粗位置"，
> SAM 给"边界在哪"，色块法给"哪一块是同一个颜色"，最后 `libs/sam-matting/scripts/mask_compose.py --union/--sub` 拼起来。
> 一条真实组合（见工作区 `mask_demo_lumine/`）：面部 = SAM(框+点)；头发 = colorblock 亮淡紫类 ∪ 暗紫类
> （同色两类按色调分开跑再并集）；上衣 = colorblock 把所有"确定不是上衣"的东西（橙底、四肢皮肤）当**隐藏竞争类**先抢走。
> 三条路各出各的，最后 `libs/sam-matting/scripts/mask_compose.py --union/--sub` 按顺序互斥合成，报告里逐类给面积与成分。

> **用途决定要不要为路 2 花钱**：**重绘**不需要那么高的精度——姿势微调、加物件要的是**比目标更大的空间**
> （轮廓 + 外扩），掩版略大反而更好用 ⇒ 重绘先看路 1/3/4（免费），只有"**分不清是谁**"或"**被遮挡**"
> 才为了语义正确花钱。**抠图**正相反：精度直接决定成品，而路 2 实测**比 SAM 干净一个数量级**
> （空洞 3.5k vs 29.2k px，单张 1024×1536 双人图，n=1）。

## 2. 路 1：检测框 / 骨架（本机免费，默认先试它）

```bash
# 部件（手/脚/头/脸/口塞/眼罩/眼，外加 mouth = 脸框下 42%）
python scripts/check_parts.py --src IMG.png --out out --feature-masks

# 整人：骨架膨胀 + 头框内接椭圆（形状贴人，不填腿间空隙）
python scripts/check_parts.py --src IMG.png --out out --person-masks \
  --person-mask-prompt pose --person-mask-cover skeleton

# 只做一个肢体：取该关节坐标（check_parts 的契约 JSON 里有 x,y），在该点膨胀
python libs/sam-matting/scripts/mask_compose.py --like IMG.png --circle 806,404,60 --grow 8 --feather 12 --out arm.png
```

- `--person-mask-cover` 取 `skeleton`（默认 `auto` 会先试它）优于 `hull`（凸包把骨架间空隙整块吞掉）；
- **贴身双人**（两人各占 >30% 画面、直立或坐姿重叠）试 `--person-mask-prompt ownbox`：它把 SAM 的框提示从「本链关键点凸包 + 10% pad」换成「本链自己的 person 框」，实测切分前两掩版重叠比 0.93–1.00 → 0.03–0.84、掩版对自身人框 IoU 中位 0.269 → 0.533（7/7 张全赢）；但横躺/多人图会变差（0.179 → 0.162，3 好 2 坏），所以**不要改默认**，按图选。切分后成品重叠恒为 0，这个开关的价值只在切分前看；
- **单肢体**用 `--circle` 在该关节处膨胀即可：肘/腕/膝/踝都能这么取（半径按身高比例，
  经验值 ≈ `0.06~0.10 × 身高`）；要更贴形状就 `--union` 两个关节圆再 `--grow`；
- 强重叠姿态下"检测框 ↔ 骨架链"的配对会出错（实测出现 person 框因 `no_skeleton` 被丢弃），
  这时加 `--allow-box-only-persons --no-merge-overlap`，代价是可能出多于两人的掩版，需要裁掉多余的。

## 2b. 路 1b：SAM（本机，边界贴形状的那一步）

```bash
# 套件的 SAM 入口：框 + 正点 + 负点，可选 --pick largest / --merge
python "<ANIME_DET_SUITE>\scripts\sam_point_mask.py" \
  --image IMG.png --box 205,275,440,500 --point 300,315 --point 350,410 --neg 320,280 \
  --pick largest --out m_face.png --overlay ov_face.png
# 技能自带的那支（同族接口）：libs/sam-matting/scripts/sam_object_mask.py
```

**什么时候用它**：目标的边界靠**纹理/形状**而不是颜色（脸、手、不规则道具）；或者你已经有一条粗糙版
（检测框 / 内接椭圆 / 色块）但边界不够贴 —— 这时 SAM 是"把边切干净"的裁判。

**同一件东西散成几块、又和邻居同色时**（布料 vs 皮肤、白布 vs 床单）用多块版：
`<ANIME_DET_SUITE>\scripts\sam_multi.py`
（**正种子 → 提议按 SAM 自评分选；负种子 → 它的承载块 → 从结果里减掉**）。三条实测：
① **别用颜色给提议投票**（负样本皮肤与目标白布本来就近同色 ⇒ "离谁更近"会把正确提议误杀，实测 dpos 5 / dneg 2 被否）；
② **负点各跑各的**、取"含该点且面积最小"的承载块再减（把多个负点混起来取中位色会得到不存在的颜色）；
③ **"邻接回收"能不开就不开**：它能补漏给的碎片，但也会按"邻接+无负点"把同色背景/床单链式并进来
（实测 4.2% → 12.7%），**能给齐种子（衣身+两只袖子+荷叶边）就别开它**。

四条**实测**规矩（713×1200 单人插画）：

1. **一定给框**。只给 7 个正点、不给框的那次把 GPU 跑到 100% 十分钟没返回（只能 kill）；
   给一个覆盖目标的框 + 2~3 个点，**1.2~2.2 秒**就回来。
2. **它给的是"皮肤"不是"脸（含五官）"**：眼睛/嘴会成为内部孔洞 ⇒ 合成时 `binary_fill_holes`，
   或者把眼/嘴也当正点加进去（"面部包含五官"这个口径要显式说清）。
3. **掩版可以进加减法**：`mask_compose.py --union/--sub` 拿它和几何图元、色块掩版拼；
   反过来也可以把它当"候选区"再喂给色块法细化。**但别默认把已有掩版当输入提示**
   （套件的 `sam_point_mask.py --mask-input`）：在色块/绳子基准上，加了它通过率从 29% 掉到 8%
   （McNemar p=0.021，n=53）—— 该用点/框提示，掩版的加减放在**后处理**里做。
4. **一张图可以多次调用**：脸给一个框、手给一个框，各出各的，最后按类合成；SAM 不负责"哪个类"。

## 3. 路 2：云端分色（**先切片、先过闸门**）

```bash
# 0) 合规闸门：BLOCK 的图不上传；REVIEW 的图只上传"目标所在的切片"
python libs/wd14-gate/scripts/wd14_gate.py IN.png
# 1) 切片（只传需要的局部：省钱 + 少暴露画面内容），坐标记下来，回来要换算
python tools/crop_view.py IN.png out/slice.png 700,600,1250,1080 --scale 1.0
# 2) 云端分色（示例：目标涂纯红、邻居涂蓝、其余纯黑）
python scripts/bailian_image_edit.py edit out/slice.png out/colorblock.png \
  "把图中<目标>的像素全部涂成纯红色 #FF0000；把<邻居>涂成纯蓝色 #0000FF；其余全部涂成纯黑色 #000000。
   输出纯色块分割图：不要细节、不要阴影、不要渐变、不要文字。" \
  --model wan2.7-image
# 3) 分色 → 掩版（灰度 + 可直接喂 ComfyUI 的 RGBA）+ 质检
python scripts/tools/mask_from_colors.py out/colorblock.png --out-dir out/masks \
  --rgba-base out/slice.png --colors "red=#FF0000" --preview
```

**实测数字**（膝枕双人图 1024×1536，两条人掩版）：8.1 秒 / 按次计费；
纯色纯度 99% 落在四色 ±60 内；两块 **0 px 重叠**；红 81% 落在对应 person 框内；
输出被模型放大到 1672×2508 ⇒ **必须最近邻缩回原尺寸**。

- 价格：默认（服务端改写提示词）$0.027504/张；**`prompt_extend=false`（本工具默认）$0.01434/张 ≈ ¥0.10**
  —— 掩版/分色这类指令**本来就不该被改写**，关掉既便宜又听话（`bailian_image_edit.py` 默认关，`--prompt-extend` 开回来）。
- 颜色**不要和画面本身撞**（红绳/红底就别用红，改品红 #FF00FF），并把"不要渐变/不要细节"说死。
- 本机实测的坑：这个账号上 `qwen-image-edit-max` **404**（没有该模型）⇒ 先用
  `python scripts/bailian_image_edit.py list` 确认可用模型名；**红线内容会被服务端审核直接拒**
  （`DataInspectionFailed`），这条不是提示词能绕的 —— 遇到就走路 4/5。

## 4. 路 3：网格数格子 → 矩形 / 内接椭圆

```bash
# 1) 叠网格：标注的是**原图坐标**，可以直接把肉眼读数当坐标用
python tools/crop_view.py IMG.png out/grid.png 700,300,950,560 --scale 3 --grid 25
# 2) 读数 → 矩形；圆/方物体用内接椭圆（不吃四个角）
python libs/sam-matting/scripts/mask_compose.py --like IMG.png --ellipse 812,340,930,455 --grow 6 --out apple.png
python libs/sam-matting/scripts/mask_compose.py --like IMG.png --box 770,326,842,492 --grow 6 --out prop.png
```

- 规则：**标签必须是原图坐标**（要心算的标签，人和 agent 都会读错）；
  100 px 网格配 1.5× 视图是甜点，**局部放大到 3× 时用 25 px 网格**（本次实测：3× + 25 px 能读准到 ±2 px）；
- 圆/方物体（苹果、球、头、按钮）**用内接椭圆**：矩形会多吃四个角的背景，重绘时那些角会被一起改；
- 这条路只回答"大致在哪"，边界**不贴形状** ⇒ 细长目标或遮挡场景别用它兜底。

## 5. 路 4：切片 + colorblock 加减法（周围简单、目标突出时最省）

**思路**：不是"把目标切出来"，而是**做减法** ——
① 用网格框定 ROI，**框外确定没有目标**；② 把"确定不是目标"的东西（背景、白布、口球这种好认的）
也**给种子**，让它们作为独立类别参与竞争；③ 目标由"谁先到"决定，边界由颜色跳变 + 描边屏障决定。

```bash
# 1) 切到目标所在区域并放大 2×（坐标换算：原图 = 偏移 + 裁剪坐标/2）
# 2) 多类竞争：目标 + 各类负样本（背景/衣服/其他物体），ROI 逐类给
#    --seed = 目标上的点（话筒：球头 + 柄中轴）；--neg = 确定是背景（白）的点
python "<ANIME_DET_SUITE>\scripts\colorblock.py" \
  region2x.png --mode compete \
  --seed 172,116 180,144 190,170 224,210 \
  --neg 420,120 370,250 330,100 184,302 \
  --roi 110,40,310,370 --lam 2.0 --tau-global 40 --budget 220 \
  --fill-holes --out mic.png --overlay mic_ov.png
```

（多类一次出图、带 ROI/负样本/成分报告的驱动脚本见工作区的 `wand_multi.py`：一份 spec 里给每类的
种子 + `roi` + `tau_global` + `budget`，输出彩色标注图 + 逐类掩版 + 每类成分报告。）

- **`--mode grow`（老行为）在"前沿漂移"上会翻车**（实测话筒案例）：皮肤的前沿漂到手指旁的白高光后，
  真正的手指橙落在 `tau_local` 之外**进不来**，而纯白满足了漂移后的阈值被标成皮肤 —— 一进一出两个方向同时错。
  `compete` 用**种子锚色**做绝对偏差门限、类间**先到先得**、跨边按"颜色跳变 × 屏障"计价，两个方向一起治。
- **种子就是颜色模型**：一个错种子会污染整类（实测把一个纯白点写进皮肤种子 ⇒ 白色成了皮肤的锚色 ⇒
  2 万 px 白背景被判成皮肤）。所以驱动器每次打**种子体检**：逐个种子与"本类锚色中位数"比距离，
  超过 `tau_global` 的标 `⚠ 离群`，先修种子再调参。
- **成分报告是必需品**：每类都要看"面积 + RGB 中位 + 暗/亮/橙占比"。本次正是靠它发现
  "掩版中位色是皮肤橙、橙占 32%" ⇒ 手被包进来了（对应报告里最想要而缺失的那个数字）。
- **节点粒度决定上限**：`fz_scale=40` 时节点约 10–20 px，手指宽 15–20 px ⇒ 指缝仍有 1 px 级锯齿；
  要 ±2 px 的边界就把 `fz_scale` 降到 25 左右（更慢）或者改用沿描边的图割。
- **什么时候别用它**：目标与邻居同色（红线 vs 红衣）、目标细长且断续（绳子）、
  目标比节点还细（发丝）—— 这些走 1/2/5。

### 5.1 边界模糊处的正解：**先外扩目标，再减掉确定的非目标**

"布料 vs 皮肤"这类边界靠**收紧阈值**永远做不干净（两者在亮部本来就重叠）。反过来做：

```
目标掩版 = dilate(色块法得到的目标, N)  −  确定的非目标（皮肤 ∩ 桃色规则）  −  遮挡物（头发/道具）
```

单次观察（`mask_demo_lumine/`，上衣，n=1 图）：色块法出 43,443 px 在肩线溢到皮肤；外扩 10 px →
63,854 px，减桃色皮肤（`R−B>40 & R>190`，4,734 px）与头发（772 px），丢小碎块 → 55,625 px（6.50%），
中位色 (248,233,226) 纯白。边界因此落在**皮肤的分界线**上，而不是"白布的阈值"上。外扩同时满足本项目
"**重绘掩版宁可略大**"的口径（见打底/重绘那两篇的掩版规矩）。

1. **减法判据必须真能分开这两类**：这里用"桃色"`R−B>40`（近白布料 R−B≈22、淡紫头发 R−B<0，都在阈值外）；
   用"亮度"分不开（白布与皮肤高光同亮）。
2. **先看被减掉多少**。同一次实验用 SAM 出皮肤（28% 面积）去减，上衣从 5.15% 掉到 **2.99%** ——
   **真布料被当皮肤减掉**（被减 37,513 px，正确值 4,734 px）。SAM 给的是"它以为是同一种材质"的区域，
   **减之前对一下面积量级**。

## 6. 决策顺序（省时间版）

1. **先跑检测**（路 1）：部件/整人/单肢体，免费且准；头 → 头框内接椭圆。
2. **目标规整且孤立**（苹果、球、道具）→ 路 3：网格 + 内接椭圆，两条命令。
3. **周围简单、目标颜色突出** → 路 4：切片 + colorblock `compete`（ROI + 负样本），
   先按成分报告确认"掩版里没有别的东西"，再交下游。
4. **多人贴在一起/要按身份分** → 路 2（先过闸门、只传切片、关掉提示词改写）。
5. **前四条互相矛盾、或边界本身是判断**（一缕头发算谁的、道具算不算在身上）→ 路 5，把画布交给人。
   人给的是"判定"，比任何模型都硬。

## 6b. 有人的 ground truth 时：先对账，再动手

让人**用 PS 涂一张纯色标签图**（红/蓝/黄/绿各一类，别羽化），再用脚本按颜色读回对账：IoU、漏了多少 px、
多要多少 px、**最大的 5 片错在哪**，并出三联对照图（黄=重叠、红=我多要、青=我漏）。
这是**唯一能分清"工具能力问题"还是"我的视觉/种子问题"**的办法。
单次观察（同一张 713×1200 单人插画，上衣，n=1）：

| 误差 | 量 | 归因 |
|---|---|---|
| 漏掉**腰部白色缠布/蝴蝶结**（同一件衣服的另一块） | 41,933 px = 全部漏的 86% | **我的**：没认出"它和上衣是同一件"，种子只给了躯干+两袖。补种子后 IoU 0.134 → 0.417 |
| 多要胸口/锁骨下方 | 14.8k + 9.6k px | **一半工具**（白布与皮肤数值同色 (249,233,226)/(250,229,223)，色块法原理分不开；SAM 靠描边能分，但负点放错会把布料减掉——用"减掉>35% 就告警"兜住）、**一半判断**（缝在哪要人定） |
| 看 GT 面积大 20% 就把面部外扩 3 px | IoU 0.728 → **0.691** | **我的想当然**：GT 的面部不含耳朵/发缘，外扩是多要 |

⇒ 三条规则：
1. **给种子前先把"这件东西都有哪些块"数一遍**（衣身 / 两袖 / 荷叶边 / 腰部缠布与蝴蝶结）；
   同一物件的每一块都要有种子，否则漏的一定是"我没认出来的那一块"；
2. **别用"面积差"当外扩/收缩的依据**，先用对账的"漏在哪/多在哪"定位；
3. 对账后调参得到的 IoU 是**自评（in-sample）**，汇报时改前改后分开写。

## 7. 不管走哪条路，交付前都要做的三件核对

1. **叠加图核对**：`scripts/tools/mask_overlay.py BASE.png MASKS_DIR --out check.png`
   —— 打印每块的像素外接框并出叠图。**多人强重叠时掩版的编号/JSON 的 person_id 都可能与直觉相反**
   （实测踩过：掩版喂反 ⇒ 用"闭眼睡觉"的提示词重绘了另一个人的脸，眼睛颜色当场串味）。
2. **不重叠**：两块人掩版必须 0 px 重叠（`check_parts.py --person-masks` 默认如此；分色法靠阈值本身互斥）。
3. **哨兵验证**：重绘 **A** 之后 **B** 的特征不该变 —— 挑一个醒目的哨兵（如"胡桃的眼睛是红的"）逐遍检查。
   掩版干净时 `SetLatentNoiseMask` 不会污染掩版外；**不要用"贴回"（ImageCompositeMasked 之类）补救**，
   那一定会出边缘问题。

另外两条**判据**（数字，不靠眼）：

- **渗出**看 **8/255**：掩版外差异 >2/255 的 ~8% 全是 VAE 编解码往返噪声底，别当渗出（实测数字）；
- **掩版尺寸**：面积 % + 外接框 + 叠图一起报（40 px 直径的小物体要 ±2 px 级边界，
  框级输出差一个数量级 —— 这是"检测框不能当精确掩版"的量化理由）。
