# 人物特征获取：从"设定资料"到"能渲染的 tag"

**目标**：产出一张**底模能渲染的特征 tag 表**（发色发型 / 瞳色瞳形 / 服装与配色 / 饰品道具 / 体型 / 标志物），
不是产出一段设定介绍。

**判据**：**tag 语料库是模型的母语，资料站只是事实来源。** 资料站告诉你"她穿黑军装、腰佩长剑"，
你得自己翻成 `black military uniform, sword`；翻不成 tag，就等于没查。

## 一、来源阶梯（按顺序用，别跳级）

## 二、百科 → tag 的翻译规则（最容易出错的一步）

- **逐项翻，不整句抄**：`银色长发、红色瞳孔、黑色军装外套、腰佩长剑` ⇒
  `silver hair, long hair, red eyes, black military uniform, sword`（IL 用 tag、Anima 可用句子，见 `prompt_writing.md`）。
- **非渲染项不进提示词**：年龄、身高体重、cv、性格、剧情、人际关系、能力设定 ✗。
- **名字以 ② 校准**：百科名 ≠ danbooru tag（系列后缀、下划线、罗马字差异），统一写成 `角色_(作品)` 的 danbooru 形式。
- **一词多义先查词义**再写：按字面画的教训见 `prompt_writing.md` §9。
- **只抄特征，不抄构图**：参考图的姿势、镜头、场景、光线不是这个角色的属性。

## 三、看图兜底（允许，但按门控走）

顺序固定，不许倒过来：

1. `python libs/wd14-gate/scripts/wd14_gate.py IMG...` —— 与 `references/output_safety_gate.md` 同一套闸门；
2. `OK` ⇒ 可以 `read_image`；`REVIEW` 只在关注标签温和时看；
3. `BLOCK`（或本就不想让图进上下文）⇒ 用 **`dsh_show_gallery`** 让人看，或**请用户口头描述**特征 ——
   **不要**因为"这只是参考图"而破例；
4. 图是 LoRA 预览图且 sidecar 里有 `meta.prompt` 时，**读 JSON 比看图更准**，也不进上下文。

## 四、产出与复用

- 把该角色的**特征 tag 表**落到任务目录 / workflow JSON 备注（一句一行、按组），供同一 task 复用；
- `tag_review` 的"场景清单"直接引用这张表（服装/发色/瞳色就是一致性锚点）；
- 换底模后**重新校准一次拼写**：不同语料库的 tag 名可能不同。
