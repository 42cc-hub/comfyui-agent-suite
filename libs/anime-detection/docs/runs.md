# 实验记录（anime_detection_suite）

> 每跑一轮就追加一行：日期 / 数据 / 参数 / 指标 / 结论。**只记诚实数字**，失败与作废的结论也留着（避免重复踩）。

## 环境与硬件
- 预标注：conda `anime_det`（imgutils + onnxruntime + PyQt5，CPU）
- 训练：conda `me2`（torch 2.13.0+cu130 / ultralytics 8.4.128），GPU = RTX 3060 Laptop **6.4 GB**
- **可用绝对路径传 `--data`**：ultralytics 会把相对路径解析到它 settings 里的 `datasets_dir`（本机那是个别的项目的目录）

## 轮次记录

### R1 · det 冒烟（3 epoch，30 张）
`--task det --imgsz 512` → 显存 **1.64 GB**、推理 7.6 ms/张；mAP 垃圾级（数据太少）。**结论：管线通、6GB 够。**

### R2 · pose pilot（20 epoch @768，30 张）
**75 秒**跑完；bbox `P 0.54 / R 1.00 / mAP50 0.82`；**18 点关键点 P/R/mAP50 = 0**。
**结论：框学得快、关键点学不动**；且我们的 pose 标签来自 dwpose 预标注（未人工修正）⇒ **M1 的瓶颈是标注质量**。

### R3 · M3 五类 v1（47 张标签）
val 缺类 → ultralytics 直接报 `requires 5 classes, not 3`。**结论：小数据集必须按类别分层切分。**

### R4 · M3 五类 v2（47 张，分层切分）
`train 38 / val 9`，val top1 0.667；混淆矩阵显示**退化成多数类**（bad_count/not_* 全判 ok）。
**结论：需要类别平衡。**

### R5 · M3 五类 v3（132 张标签，过采样到 256）
val top1 **0.714**；`ok 13/13` ✓，但 **`bad_count` 0/3** ✗。
**结论：五类下"数量错误"这一类抓不住。**

### R6 · M3 五类 v4（裁图外扩 10% → 30%）
val top1 **0.619**（更差），`bad_count` 仍 0/3。**结论：外扩裁图是死路**（"模型看不到肢体上下文"的猜想被否掉）。
（附带发现：`recut_crops.py` 重裁后 181/182 条标签可按裁图名复用。）

### R7 · M3 **二元** ok/bad v5（132 张，过采样）
val top1 **0.800**；bad 召回 **0.43**（3/7）；**逃出收容所基准 12/12 命中**，4 处已知缺陷（test1 手/脚、test6 脚、test7 脚）**全部判 `bad`** ✓（`test_1_left_foot` 在五类版是漏的）。
**结论：产线只要"能不能用" ⇒ 二元任务更对**；细分标签保留在 `index.csv` 不丢。

### R8 · M2b 面部组 v1（自动标注蒸馏：head 裁 256×256 → imgutils 脸/眼 → 训练）
数据：`ds_face` 256 裁剪图 `train 134 / val 35`，499 框，类别 face/eye。
指标：`face` P 0.972 / **R 0.872** / mAP50 0.955；`eye` P 1.00 / **R 0.106** / mAP50 0.959；全体 mAP50 0.957。
**结论：脸能学到（自动标注源够用）；眼召回极低 ⇒ 自动标注源（imgutils 眼检测）在紧裁图上的标签太稀**，要么换更密的标注源，要么这一层先不上。
**这印证了"标准画布"的价值**：256 固定尺度下 40 epoch 就有 0.955 mAP50。

### R9 · M3 **三元** ok/bad/not_part（132 张）
val top1 **0.700**（< 二元的 0.800）。**结论：数据量不变时类越多越差**；`not_part` 这类（部位认错）本质是 **M2a 的问题**，
不该和 M3 的 bad 混在一起 ⇒ 生产上用二元 + 单独的 `not_part` 队列。

### R10 · 预标注扩池到 **308 张 → 605 张裁图**（逃出 8 + temple 分层 300）
数据集同步长大：`ds_det` 246/62、`ds_pose` 246/62、**`ds_face` 326 张 256 裁剪 / 1171 框**。

### R11 · 主动学习挑样（第一版，`mine_candidates.py`）
605 张池里排除已人工标注的 182 张 → 423 张候选，按 `p(bad)` + 不确定带打分取前 200 出队列。
**自己肉眼复核前 6 张发现一个要紧现象**：高分候选**多数是"部位认错"**（画面里明明是脚，却被手检测器框成 `hand`），
不是"指/趾数量不对"。原因：训练时把 `not_hand/not_foot` 并进了 `bad`，模型对"这不是手"给高 `p(bad)` —— 判定本身没错，
但这类样本喂 M3 是浪费，**它们真正该喂 M2a（当负样本）**。
- WD14 的 `mismatch` 只抓到 **17/423**（紧裁图上下文不足 ⇒ 标签稀疏，不可靠）；
- 改用**姿态关键点**判部位（腕/踝/趾点是否落在框内）→ 抓到 **22/423**，仍偏低（dwpose 会"推断"看不见的手 ⇒ 也有假点）。
- 结论：**部位判定本身是个小课题**，暂时接受"队列里混着少量部位错样本"，让标注者一键 `not_part` 标掉（这类标签顺便就是 M2a 的负样本）。
  产物：`data/cls_queue_mined/`（M3 用，200 张）+ `data/cls_queue_mined_mismatch/`（M2a 负样本，22 张）。

### R12 · 产线入口 `locate.py`（fallback 路径实测通过）
3 张逃出图跑通：输出统一契约 JSON（`points/boxes/flags/chain`）+ 可选手/脚蒙版。
在缺我们权重时自动回落到 imgutils；两个环境各有半边（`anime_det` 有 imgutils 无 torch；`me2` 有 torch 无 imgutils），
所以入口做成**每层软依赖**（缺了就记 `*_unavailable` flag，不中断）。
**待办：把我们的模型导出 ONNX，让产线在无 torch 的环境也能跑**（现在 me2 才能用我们自己的权重）。

### R13 · M2b 面部组 v2（数据从 134 → **326** 张 256 裁剪）
`face` P 0.985 / **R 0.992** / mAP50 0.995；`eye` P 0.958 / **R 0.960** / mAP50 0.978（全体 mAP50 **0.986**）。
**结论：眼睛召回从 0.106 → 0.960，纯粹是数据量的功劳**（架构、参数、画布都没动）。
⇒ "固定标准画布 + 足够数据" 这条路在一个模块上**已经跑通**；M2b 可以认为基本解决。

### R14 · M1 骨架：schema 才是瓶颈（两次失败 + 一次改法）
| 版本 | 数据 | schema | bbox mAP50 | **关键点 mAP50** |
|---|---|---|---|---|
| v2 | 246 张 / 60 ep | OpenPose18（含 neck） | 0.862 | **0.01** |
| v3 | 246 张 / 60 ep | OpenPose18，**丢弃 119 个低置信实例** | 0.773 | **0.02** |
| v4 | 246 张 / 60 ep | **COCO-17（复用预训练头 + 正确 flip_idx）** | 跑中 | 跑中 |

**结论：不是数据量、不是标注噪声，而是 schema** —— `yolo11n-pose.pt` 的预训练头是 COCO-17，
用 OpenPose18（把 neck 塞进去）等于把头重新初始化、从零学 18 个点，60 epoch 学不出来。
v4 把 dwpose 的点映射到 COCO-17 顺序（`COCO17_FROM_BODY18`）复用预训练头 —— 这是"从零学 vs 微调"的差别。

### R15 · M2a 检测（308 张 / 1500 框，yolo11n @768，100 epoch）
脱离会话训练中（`runs/_logs/m2a_det_v1.log`）。用它的意义：① 让产线入口在**没有 imgutils 的环境**也能跑；
② 量化"我们的 det 能否复现自动标注器的召回"。**注意**：标签来自 imgutils（含"脚被当手"的错），
所以这份权重会继承同样的偏差 —— 它的价值是**统一接口与离线可用**，不是超越标注器。

### R16 · 自训练（伪标签）**无效**（如实记录）
用二元 v5（val 0.80）给池内 423 张未标注裁图打伪标签，阈值 >0.90(bad) / <0.10(ok)：
**两类各 0 条**。说明这版模型的**整体置信度不高**（112 张训出来的），阈值一放到能产出样本就会注噪声。
⇒ **伪标签要等基准模型更强之后再做**；当前瓶颈仍然是人工标签量。代码留着（`--pseudo-weights`），不是删掉。

### 工程坑（2026-10-11，都踩到了才记）
1. `train.py --task det` 会让 checkpoint 里 `task='det'`，而 ultralytics 的 `predict/val` 只认 `'detect'`
   ⇒ 直接加载权重预测会报 `does not support 'predict' mode for 'det' task`。已双向修：训练侧规范成全名，消费侧也兜底改写。
2. `locate.py` 曾为了几个常量 `import prelabel_batch` —— 而那个脚本顶层就 `import imgutils`，
   在没装 imgutils 的环境直接崩 ⇒ **产线入口的点名字表已内联**（入口不该依赖预标注脚本）。
3. 两个 conda 环境各有半边：`anime_det`(3.10) 有 imgutils/onnxruntime/PyQt5 无 torch；`me2`(3.14) 有 torch/ultralytics/onnxruntime 无 imgutils
   （`dghs-imgutils` 在 3.14 装不上，依赖没有轮子）。⇒ 入口做成**每层软依赖**。

### R21 · 选权重必须用**交付图**而不是 val 划分（重要教训）
| 权重 | val 关键点 mAP50 | 交付图上 8 张检出人 |
|---|---|---|
| `m1_pose_coco17`（v4，60 ep） | 0.349 | **7/8**（@1280） |
| `m1_pose_coco17_v5`（150 ep） | **0.457** | 5/8（@1280） |
⇒ val 来自同批 ~1200px 语料，交付稿是 **2000px + 另一条渲染管线**；**val 上更好 ≠ 交付图上更好**。
产线默认权重因此定为 v4，并把推理分辨率默认提到 **1280**（640 时只有 5/8）。

### R22 · 专用脚检测器（单类）+ 三级并集（**含一次自我纠错**）
- 单类脚模型（`ds_foot`：569/214，1495 框）val mAP50 **0.572**，与 4 类里的 foot（0.577）基本持平 —— 单看这个指标它没优势；
- 训练**中途**读 `best.pt` 做交付图验收时，曾看到"4 处已知缺陷报出 3 处"（test1/test6/test7）；
- **训练结束后用最终权重重跑：只有 `test1` 一处报出（1/4）**。⇒ **先前那个 3/4 是训练中途 checkpoint 的产物，数字作废**。

**两个教训（都比那个数字值钱）**：
1. **`weights/best.pt` 在训练过程中会被不断覆写** —— 拿它做验收前必须先确认训练进程已退出，
   否则量到的是"某个中途快照"，结论不可复现。已把这条写进运维注意（训练用脱离会话进程 + 日志判完成）。
2. **单类模型的 val 指标可能完全不突出，但它错误的分布与多类模型不同** ⇒ 并集能补召回；
   只是"补回哪些图"**不稳定**，所以产线不能宣称"一定报得出来"。

### R26 · 主动学习队列：**我挖矿脚本里的一个真 bug**（自查发现并重挖）
`mine_candidates.py` 里我写的是 `enumerate(model.names)` —— 而 `model.names` 是 **dict**，
`enumerate` 出来的是 key（0/1 整数），所以 `n == 'bad'` **永不匹配** ⇒ `bad_i` 为空 ⇒
`p_bad` 退化成 **top-1 置信度** ⇒ 挑出来的其实是"**模型最有把握的 200 张**"，不是"最可能是 bad 的 200 张"。

证据与修法：
- 给第一版队列补 `p_bad` 后发现 **169/200 其实 p(bad)<0.5**（自相矛盾 ⇒ 定量暴露了 bug）；
- 改成 `[i for i, n in model.names.items() if n == 'bad']` 后重挖：**200/200 都是 p(bad) ≥ 0.9**；
- 池子同时涨到 **1971 张裁图**（996 张图），待筛 1789 张；"部位认错"负样本队 22 → **103 张**（给 M2a）；
- 旧队列留档 `data/cls_queue_mined/index_v1_badrank.csv`（**没有覆盖任何人工标签**，当时标签为空）。

顺带新增：`scripts/add_pred_to_queue.py`（给队列补 `p_bad`，保留人工 label）、
`scripts/prefill_queue.py`（把"穿鞋/穿袜 ⇒ skip"这类**规范可判**的行预填掉；本期队列没有 covered/shod，实填 0 张）、
`scripts/retrain_m3.py`（判完一条命令：导出→训练→混淆矩阵→已知缺陷验收）、
`scripts/compare_with_imgutils.py`、`scripts/eval_pose_finals.py`。
标注器现在会显示**模型提示**（`p(bad)`），你判的时候可以直接确认或推翻（这同时也在量模型的 FP/FN）。

### R27 · M1 骨架：数据 738 → **1129 实例**（120 epoch @768，1.19 小时）⇒ **val 关键点 mAP50 0.835**
| 版本 | 数据 | bbox mAP50 | **关键点 mAP50 / mAP50-95** |

### R32 · 下一批队列**前置过滤**：用你判过的 382 张反推门限（用户 2026-10-11 批准）
R30/R31 已经指出：上一批 200 张里 46% 根本不是该部位、30% 是 `skip`，人的时间一半花在废样本上。
用户 2026-10-11 同意"过滤器可以加"。做法不是拍脑袋定阈值，而是拿**已标注的 382 张当验证集**
（`.runtime/gate_final.py`），穷举四个可计算门限的组合，看 Pareto 前沿：

| 门限组合 | 剩 | 真错误留住 | 挡掉部位错 | 挡掉 skip | 队列密度 |
|---|---|---|---|---|---|
| 不过滤 | 382 | 35/35 | 0/111 | 0/113 | 9.2% |
| 短边≥64 | 307 | 34/35 | 46/111 | 21/113 | 11.1% |
| 检测置信≥0.6 | 177 | 25/35 | 89/111 | 60/113 | 14.1% |
| 姿态不矛盾 | 77 | 16/35 | 109/111 | 98/113 | 20.8% |
| **conf≥0.5 + 短边≥64 + edge≥4** | **170** | **28/35（80%）** | **101/111（91%）** | **66/113** | **16.5%** |
| conf≥0.6 + 短边≥64 + edge≥4 | 140 | 25/35 | 104/111 | 76/113 | 17.9% |

**默认取 `conf≥0.5 / 短边≥64 / edge≥4`**（recall 优先，和本项目"宁可多报"一致）：真错误密度 9.2% → **16.5%（×1.8）**，
同时挡掉 91% 的"根本不是该部位"。三个门限都是现成量、零额外模型、单张成本约 1 ms：

| 门限 | 为什么 |
|---|---|
| `conf` M2a 检测置信度 | 低置信框大量落在空白处 |
| `side` 裁图短边 | 太小的裁图根本数不清指/趾 |
| `edge` **128×128 灰度平均梯度幅值** | "框里到底有没有东西"的代理量 |

`edge` 是这轮**人眼看联系表才发现**的：`not_foot` 那批（人判"不是脚"，姿态点却落在里面）里大量是
**纯色墙、路面、天空、布料、火焰、皮肤**——检测器 0.3~0.75 置信度也照报，`pose_verdict` 也判成脚
（`.runtime/montage_notfoot.png`）。这类"框在空白处"的可计算特征就是**几乎没有梯度**
（`not_foot` 中位 edge 3.26，`ok` 8.32，`bad_count` 10.02）。

**两个反直觉的实测结论**：
1. **姿态自洽单独用最"纯"（密度 20.8%）但召回只 46%**；一旦有 conf/size/edge，姿态项几乎不再加分
   （140 vs 142 张、真错误一样 25）⇒ 默认**不启用**姿态门限，省掉 prelabel JSON 解析。
2. `state`（WD14 的 covered/shod）在**紧裁图**上几乎不触发（382 张里只有 23 张非 bare/unknown）⇒
   它不能当门限，只能当弱信号（老逻辑里的降权保留）。

落地：`scripts/mine_candidates.py` 新增 `--min-conf/--min-side/--min-edge/--no-gate`；
被挡掉的样本**留档**到 `<out>_gatedout/index.csv`（含 `gate_reason`/`edge` 两列），它们是 **M2a 的难负样本素材**
（"这里没有手脚"本身就是检测器该学会的负样本）；另外 `--weights` 现在可给**多个** M3 权重取 `p(bad)` 最大值
（与产线"任一报警即可疑"一致），WD14 只对**过门限的**裁图跑（0.9s/张 ⇒ 省掉一半以上时间）。

**纪律提醒**：这套阈值是在 **35 条真错误**上标定的，样本很小；所以全部做成命令行开关，
换一批标签后应重跑 `.runtime/gate_final.py` 再定，而不是把 0.5/64/4 当真理。

### R34 · M2b 口径连改两次（用户实测推动）——**预标注取消**，并修掉一个会覆盖人标的 bug
**一、预标注被实测否决。** R33 的设计是"先复核预标注、通过就一键采纳"。用户判了 41 轮后的真实分布：

也就是说**预标注 0% 被采纳**（而且人画的框普遍比预标注更紧、位置也有偏移）。用户原话：

⇒ 未判轮次**不再画预标注**；只剩两个动作：**鼠标拖框 = 有目标**、**按 1 / 3 = 没有这个目标**；
`verdict` 改用 `draw` / `neg`（老 `pass`/`fail` 仍可读、可显示、可导出）。`prop` 列保留在 CSV 里只作记录
（它现在是"这个先验有多差"的证据，不再进界面）。

**二、标注器自己会写坏数据（用户报的）。** 用户画完框往前翻，回头看发现**看不到自己的记录**。
根因两条：① `show_row` 回头看时只重画了**原始预标注**，从没画过 CSV 里存的人画的框；
② 更糟的是当时**没有"画布是否被人动过"的标志**，于是再翻一页时程序把画布上那个预标注
**当成人的结果写回 CSV，覆盖了人画的框**。证据：有 3 轮的 `boxes` 与 `prop` 逐位相同却被判 `fail`
（自相矛盾），这 3 轮已退回未判重标。

修法：已判轮次**显示记录本身**（绿框）；原始预标注降级为 `ref`（虚线青、只画不存）；
加 `dirty` 护栏 —— **画布没被人动过就绝不允许覆盖已存记录**；顺带修掉"只点一下预标注框（没拖动）
也被算成人改过"的假阳性。修前整份队列备份在 `data/m2b_queue/index_before_fix.csv`。

"回头看显示记录"、"来回翻页不覆盖"、"清空框后退回未判"、"老口径仍可读"）。

**教训**：标注器是**往训练集里写数据**的代码，和训练脚本一样需要"能失败的自检"。
这次是**用户的眼睛**发现的（我的 12 项自检全过却漏了它）——因为自检只覆盖了"我想到的路径"。

### R35 · **用户发现队列设计的系统性漏洞：半标注 = 教模型"这里没有"**（这一条比前面所有调参都重要）
用户 2026-10-11 标完 M2b 后提出：「有的图中 gag 和 blindfold 都有，但它只问了我其中一个，所以另一个
就没有被标注，甚至有时候是有口塞却在问眼罩，那么我自然就标注了没有。这些数据拿去训练 detection 可能会有问题。」

**他说的完全对，而且量化后比预想严重。** 轮次原来是"按 WD14 命中的目标"生成的 ⇒ 同一张 head 往往只问一个目标。
在检测训练里**没标的目标就是背景**，所以：

| 事实（本机实测） | 数字 |
|---|---|
| 队列覆盖的 head | 289 张，其中**只问了一个目标**的 | **278 张** |
| 队列**外**的 head | 1173 张，其中 WD14 说"有口塞/眼罩"的 | **442 张** |
| 全池 WD14 命中的 head | 605 张，人工只覆盖了 | 163 张（27%） |

也就是说：**如果把 gag/blindfold 直接并进 `ds_face`（1462 张）去训一个四类模型，
会有 442 张"很可能真有目标"的图被当成"这里没有"的监督** —— 不是噪声，是**系统性地教模型压制这两个类**。
（同理，队列里那 278 张缺的那一半目标也在教同一件事。）

**处置（三层）**：
1. **补全覆盖**：新脚本 `scripts/m2b_complete_coverage.py` 给队列里每张 head 补上缺的目标轮次
   ⇒ 300 → **578 轮**（补 229 个 blindfold + 49 个 gag；其中 **43 轮 WD14 有命中** = 大概率真有目标却从没问过）。
2. **训练入口装闸**：`export_face_extra.py` 只导出**每个目标都问过、都判过**的 head
   （另外写 `_coverage.csv` 留档，并自动清掉过期标签防误导）；实测它把当时 299 轮里的 **277 轮**挡在外面，
   只放行 11 张完全覆盖的（守卫生效）。
3. **不再并入 `ds_face`，改成专用小检测器**：新增 `data/ds_face_gag`（`build_dataset.stage_gag`，
   类别 `0 gag / 1 blindfold`，256 的 head 裁图），**只收覆盖完整的 head**；M2b 本体（face/eye，全 1462 张）
   维持原样不动。这与项目里已有的"单类专用模型"（`m2a_foot_v1`）是同一个模式。
4. `m2b_propose.py` 的**根因也修了**：现在只要一张 head 入选，就把它的**每个目标都问一遍**

### R39 · **M3 的"卡在分类器"结论要撤回一半：训练与推断的脚裁图口径不一致**（今天最有价值的一条）
起因：查"交付图 08（test7 趾多）为什么三个 M3 都不报"。链路是：

1. test7 在训练队列里**标过 `bad_count`**（标对了），三个模型对**那张训练裁图**都给 p(bad)=**1.000**；
2. 但产线对同一场景给的裁图，三个模型都给 **0.00**；
3. 同一张图（`references/originals/test (7).png`，832×1216）严格对照：
   | 裁图口径 | 尺寸 | v7 / aug / review |
   |---|---|---|
   | **训练口径**（`prelabel_batch`：姿态脚点包围盒 + 0.35 外扩） | 229×103 | **1.00 / 1.00 / 1.00** |
   | **产线口径**（`locate.py`：检测器脚框 + 0.10 外扩） | 247×415 | **0.00 / 0.00 / 0.00** |
4. 更糟的是**框都不是同一只脚**：产线脚框 `(500,95)-(747,510)`，而被标注的那只脚在 **y≈1081**（离产线框 2.5 个框高）。
   根因：训练裁图的脚框来自 **dwpose 的 FOOT3（趾/跟三点）包围盒**，产线脚框来自**检测器**；两者不是一回事。

**顺手排除了一个更坏的可能**：模型并没有靠"裁图紧不紧/大小"这个伪线索（14 张真值 ok 在 4 个尺度下判 bad 只有 0~2 张）。
它对"脚在画面里变小"是敏感的：真值 bad 的 9 张，训练口径报 8、外扩 1.6× 报 5~7、外扩 2.6× 只报 4（v1 只 1）。

**结论（要写进纪律）**：
- 我之前说"M3 是产线唯一瓶颈"**至少有一半是裁图口径造成的假象**——分类器在它认识的裁图上是对的。
- **检测类项目的对齐检查不能只看"有没有框"**：训练裁图与推断裁图必须是**同一套几何**，否则指标会以一个看不出来的方式塌掉。
  这条与 R35（"没标 ≠ 没有"）是同一族错误：**接口口径**也是数据的一部分。
- 修复方向（两条，代价差很多）：① **产线对齐训练**（脚按"远端 + 大外扩"裁，且框源换成姿态锚点）；
  ② **训练对齐产线**（用 `recut_crops` 按检测器框重裁 996 张的脚裁图，标签按裁图名沿用，再重训）——
  ② 更彻底但要重跑检测 + 重训，且人的标签是在旧裁图上判的（虽然缺陷在旧裁图上看得清，标签仍有效）。

### R40 · R39 的收尾：**"远端脚区"检测器跨风格失败，改用收紧裁图的并列旗标 ⇒ 已知缺陷 4/4**
R39 找到的根因（训练裁图 = "紧贴远端脚"，产线裁图 = "整只脚+腿"）之后，两条修法都试了：

| 修法 | 结果 |
|---|---|

| **几何收紧**：把产线的脚框按"下 40% + 宽 1.2×高"再切一次，多做一次 M3 判定，作为**并列旗标** `foot_tight_check`（默认关，`--m3-foot-tight`） | ✅ 交付图 08（test7 趾多）**被报出**：只算主判定 3/4 → **主判定 ∪ 收紧旗标 = 4/4**；代价是 02/03 两张多一个旗标 |

8 张逐图（`--m3-foot-tight`）：

| 图 | 主判定 bad | 收紧旗标 | 真值 |
|---|---|---|---|
| 01 / 06 | 1 / 2 | 1 / 2 | 无缺陷（原有误报） |

**必须写清的保留意见**：这个收紧规则是**在 8 张验收图上扫出来的**（5 个候选规则里挑的），有明确的过拟合风险；
08 上也只有三个模型里的一个给到 0.91（另两个 0.90/0.94 是对更紧的一档）。所以它是**"能让验收变成 4/4 的信号"**，

**纪律补充**：这次连踩两次同类坑 —— ① 训练/推断的裁图口径不一致（R39）；
② **跨风格的检测器不能假设迁移**（远端脚区模型在 temple 上 whatever，在我们的渲染稿上直接失效）。
两者都是"看起来是模型问题、实际是数据/接口问题"。

| 权重 | 训练数据（args.yaml） | train 裁图数 | 其中**就是** `cls_val_common` 的裁图 | 占 val（50）的比例 |
|---|---|---|---|---|
| `m3_cls_aug_v1` | `data/cls_bin_aug_test2` | 142 | **21** | **42%** |
| `m3_review_v1` | `data/cls_review` | 242 | **29** | **58%** |
| （对照）`cls_bin_v8` | 修过切分 | 354 | **0** | 0% |
| （对照）`cls_bin_prod` / `cls_bin_mix` | 本轮新建 | 350 / 704 | **0** | 0% |

⇒ **两个线上权重的 val 数字（`m3_cls_aug_v1` top1 0.78 / bad 召回 0.9375，`m3_review_v1` 0.82 / 0.875）
不能作为"召回"的证据**：它们有一半左右的评测裁图在训练集里。同理，用它们做的阈值扫描里
"并集召回恒为 1.000"也是这个原因（**该结论作废，不要引用**）。
**可用的**是两条别的证据：① 交付图 8 张（我们自己的渲染稿，训练集里绝无）上的 3/4 主判定、
4/4（∪收紧旗标）；② 交付图上扫阈值（0.5/0.65/0.8/0.9）召回不变、旗标 16→13，这条不含泄漏。

**这对项目的含义（比消融本身重要）**：M3 的**真实召回**要看本轮新建的无泄漏权重，而它们现在
在 50 张公共 val（16 张 bad）上是 **bad 召回 0.50~0.69**（见 R44）——即 M3 比一直以为的弱，
交付图上那 4/4 里至少有一张（08）是靠**在 8 张验收图上扫出来的**收紧规则兜住的（R40 已注明该风险）。
⇒ 结论与 `## 待办` 一致但更硬：**M3 的瓶颈是 bad 类样本量**，下一步只能是主动学习补 bad，而不是调网络。

### R44 · 窗口 ③：M3 消融矩阵（**网络不是瓶颈**）
16 个单元（8 个配置 × 2 个种子），全部用**修过泄漏的按图切分**数据、同一公共 val（50 裁图 / 16 bad）、
同一套交付图指标（`locate.py` 默认口径）与同一池外报出率（120 张未标注、过门限的裁图）。

| 配置 | 变量 | val top1 | bad 召回 | 池外报出 | 交付 主判定（各种子）/ ∪收紧（各种子） |
|---|---|---|---|---|---|
| `base_aug` | 按图切分 + 增强扩充少数类（现产线数据口径） | 0.82 ± 0.00 | **0.579 ± 0.076** | 0.199 | 1,1,2 / 2,3,3 |
| **`no_aug`** | **去掉增强扩充（原始已标注裁图）** | 0.827 ± 0.019 | **0.625 ± 0.055** | 0.178 | 2,1,1 / 3,2,2 |
| `crop_prod` | 按产线口径重切后重训（R39 的另一条修法） | 0.74 ± 0.06 | 0.563 ± 0.063 | 0.192 | 1,2 / 3,3 |
| `na_res288` / `na_res320` | 输入 288 / 320（骨干 n） | 0.83 ± 0.01 / 0.84 ± 0.00 | 0.594 ± 0.094 / 0.594 ± 0.031 | 0.175 / 0.183 | 1,0 / 3,2 —— 2,1 / 3,3 |
| `na_s224` / `na_s288` | 骨干换 **yolo11s** | 0.80 ± 0.00 / 0.81 ± 0.03 | 0.563 ± 0.00 / 0.50 ± 0.00 | 0.213 / **0.062** | 0,1 / 2,2 —— 1,0 / 2,1 |
| `mix_conv` | train 里同时放两种裁图口径（704 张） | 0.80 ± 0.00 | 0.594 ± 0.031 | 0.225 | 2,1 / 3,2 |

结论（都可复算：`data/ablation_m3.csv`）：
1. **分辨率（224→288/320）不提升**：top1 与召回都在噪声内，池外报出略降。
2. **更大的骨干更差**：`na_s224` 两个种子 top1 都是 0.80（`na_s288` 均值 0.81）⇒ ~330 张训练裁图撑不起 s。
3. **增强不划算**：三个种子下 `no_aug`（0.827 ± 0.019）与 `base_aug`（0.820 ± 0.000）**区间重叠 ⇒ 无差别**
   （只有 2 个种子时看起来 no_aug 两个种子都是 0.84、base_aug 都是 0.82 —— 第 3 个种子把这个"优势"抹平了。
   记在这里当纪律样本：**2 个种子同向还不够，别急着下结论**）。
4. **按产线口径重切再训最差**（0.74 ± 0.06）：人工标签是在旧口径裁图上判的，重切会切掉证据 ⇒ 引入标签噪声
   （与 R43 的交叉口径评估一致：连在产线口径上训练的模型，在产线口径上也最差）。
5. **把两种口径都塞进 train（`mix_conv`）也没换来口径不变性**：val 0.80、池外最高（0.225）。
⇒ **M3 的瓶颈是 bad 类样本量/任务定义，不是网络。** 下一步只能是主动学习补 bad（R46）。
（这一轮的最大收获其实是 R43 的泄漏审计 + 本节：此前"val 召回 0.94"的印象来自泄漏，真实值 ≈ 0.6。）

### R46 · 窗口 ⑤：**按源图分组的 5 折 OOF —— M3 的诚实指标与"阈值别乱抬"**
`scripts/cv_m3.py`（新）：把 `cls_bin_v8_noaug` 的**全部 382 张**已标注裁图（bad 167）按**源图**分 5 折
（同一张源图的裁图只在一折；271 张源图，每折 bad 33~34），每折重训、只在折外预测 ⇒ 每张裁图都有一个
"模型没见过它"的 p(bad)。两个种子各训一遍，并给出**多种子并集**（= 产线口径）的曲线：

| 阈值 | 单模型 s1 召回/误报 | 单模型 s2 召回/误报 | **并集(2 种子) 召回/误报/top1** |
|---|---|---|---|
| 0.30 | 0.814 / 0.265 | 0.689 / 0.177 | 0.844 / 0.335 / 0.743 |
| 0.40 | 0.766 / 0.205 | 0.659 / 0.149 | 0.814 / 0.274 / 0.764 |
| **0.50** | **0.743 / 0.140** | **0.629 / 0.102** | **0.790 / 0.186 / 0.804** |
| 0.60 | 0.683 / 0.130 | 0.605 / 0.079 | 0.743 / 0.163 / 0.796 |
| 0.70 | 0.623 / 0.102 | 0.569 / 0.070 | 0.695 / 0.126 / 0.796 |
| 0.80 | 0.551 / 0.074 | 0.521 / 0.056 | 0.647 / 0.102 / 0.788 |

三条结论：
1. **M3 的诚实召回 ≈ 0.74（单模型）/ 0.79（产线式 2 模型并集）**，阈值 0.5；代价是 14%~19% 的 ok 裁图被误报。
   这与 R43 的泄漏审计一起，把"M3 召回 0.94"彻底改写。
2. **阈值不要抬**：0.5 → 0.8 只省 8 个点的误报（0.186→0.102），却掉 14 个点的召回（0.790→0.647）。
   （R45 里"交付图上 0.8 旗标更少而召回不变"是 **4 个正例**上的观察，这里被 167 个正例否掉了 ⇒ **`--m3-conf` 保持默认 0.5**。）
3. **折间方差极大**：同一个种子、同一套超参，5 折的召回是 `[0.82, 0.58, 0.52, 0.94, 0.85]`，**±0.165**；
   换种子单模型召回 0.743 → 0.629。⇒ 本项目所有"单次切分 val 上差 0.05"的结论都不可信（这也是 R44 只敢按
   "两个种子同向 + 幅度 ≥0.02"来判的原因）。
   副产物：`data/cv_m3_oof.csv`（每张裁图的折外 p(bad)）以后可以直接用来挑阈值/挑主动学习样本。
4. **可复现**：整轮重跑一遍（10 次训练、按图分折不固定种子之外全同），上面每条曲线**逐项相同**
   ⇒ 结论不是抽签抽出来的（折间方差大 ≠ 结果不可复现，两者是不同的事）。
5. **误差解剖（用同一份 OOF + manifest）**：脚 **召回 0.849**（bad 93 / ok 70，误报 0.186）、
   手 **召回 0.608**（bad 74 / ok 145，误报 0.117）⇒ **手是指头数判定的短板**（脚已 0.85），
   下一批标注优先标手（R44 的结论"网络不是瓶颈"在这里得到第二重印证：脚与手用同一套网络/分辨率，
   差别只能来自数据）。

_ids = {id(x) for x in rec['boxes']}

### R49 · 窗口 ⑧：**类别口径**消融 —— 现口径的 bad 里 72% 是"框根本不是该部位"，但改成"只留数错/畸形"没有净收益（因为真正例只有 48 张）

**`not_hand`/`not_foot`（框不是该部位）126 张 = 72%**，真正的"数错/畸形"（`bad_count`+`bad_shape`）**只有 48 张**。
⇒ 现产的 M3 有一多半训练信号在教"这像不像手/脚"，而不是"指/趾数对不对"。

**做法**：`scripts/build_cls_taxonomy.py`（新）用**同一套按源图切分**造三个数据集（源图泄漏均自检为 0）：

| 数据集 | 定义 | train | val |
|---|---|---|---|
| `cls_tax_binary` | ok vs {bad_count, bad_shape, **not_***}（现口径） | 188/144 | 28/30 |
| `cls_tax_parts` | ok vs {bad_count, bad_shape}（丢掉 not_*） | 184/**40** | 32/**8** |
| `cls_tax_3cls` | ok / bad_count / bad_shape | 184/24/16 | 32/6/2 |

**① 混合 val（=现二元口径的 val，含 not_\*）上的矩阵结果**（`ablate.py --only tax --seeds 2`）：

| 配置 | val top1 | bad 召回 | 交付 主判定/∪收紧 | 池外报出 |
|---|---|---|---|---|

| `tax_parts`（只留真缺陷） | 0.80 ± 0.02 | **0.406 ± 0.031** | 2,0 / 2,0 | **0.104** |
| `tax_3cls`（ok/数错/畸形） | 0.80 ± 0.00 | **0.406 ± 0.031** | 1,1 / 2,2 | **0.046** |

在这个 val 上 `tax_*` 掉召回是**定义不同的必然结果**（它们没学过"不是手 ⇒ bad"）。所以做了下面这次**同集合**比较。

**② 同一批"真部位"裁图上的折外比较**（`cv_m3.py --src data/cls_tax_parts`，再与 `cv_m3_oof.csv` 对齐；
`scripts/compare_taxonomy_oof.py`（新））：48 个真缺陷 vs 215 张 ok，两个训练口径都在**同一批裁图**上出折外预测：

| 阈值 | 二元口径 召回 / 误报 | 只留真缺陷 召回 / 误报 |
|---|---|---|
| 0.30 | **0.583** / 0.335 | 0.375 / 0.199 |
| 0.40 | 0.542 / 0.274 | 0.333 / 0.102 |
| 0.50 | **0.500** / 0.186 | 0.292 / **0.046** |
| 0.60 | 0.417 / 0.163 | 0.250 / 0.023 |
| 0.70 | 0.271 / 0.126 | 0.188 / 0.019 |
| 平均 p(bad) | 正例 0.438 / 反例 0.262 | 正例 0.291 / 反例 0.187 |

- **等高召回**（约 0.27~0.33）：`parts` 的误报是 **0.02~0.10**，二元口径是 **0.126~0.27** ⇒ parts 明显更"准"。
- **等高误报**（约 0.10）：`parts` 0.33 vs 二元 0.27~0.30 ⇒ parts 略好。
- 但 **`parts` 的召回天花板更低**（0.375 vs 0.583）：它只有 40 张训练正例，**样本被饿死**（每折召回 `[0.00,0.40,0.20,0.30,0.00]`）。
- 二元口径还有一个副作用是"有用的"：它对**非部位**裁图的平均 p(bad)=0.873、**91% 判 bad**
  ⇒ 产线现在靠它兜住"这压根不是手/脚"；改成 parts 口径后这层就没有了（交付图上 union 从 3/4 掉到 2/4）。

**结论**：**保持二元口径**（它同时承担"部位有效性检查"），但必须把两件事写进纪律：
① **M3 的召回要在"真部位"裁图上单独报**，混合 val 上的数字会掩盖"其实只会认手"；
② 下一步标注要**专挑真缺陷**（`bad_count`/`bad_shape`）—— 现存 48 张，而队列里一眼能判的"不是手/袜子"已经够多了（R48 的档 2/3）。
3 类（数错 vs 畸形）在 24/16 张上**不可行**（与历史结论一致），作为"bad 聚合"用时与 parts 表现相同。

**顺带的两个小改动**（加法式、默认行为不变）：多类权重（无 `bad` 类）时，
`eval_m3.py` 与 `locate.py` 的 M3 判定都改为"除 ok 以外都算可疑"——否则 3 类模型会永远判 ok（这次就是靠它才能评）。

### R54 · 用户提的增强坑：**头/脸类小目标必须关掉 mosaic（切片）**，而历史模型全都开着

**两条被数据推翻的假设（值得记住）**
1. **"标签里有重复口塞框 ⇒ 模型会吐重复框"——错。** 按用户 10-12 的判据（小框被更大的同类框包住 ⇒ 取大的）
   在 `build_face4.py` 加了包含去重，口塞框 480 → 464；但 val 重复框率只从 0.045 → 0.03，
   交付 gag 16/18 vs 未去重版的 17/18 ⇒ **重复框来自检测头在 conf 0.4 下的 NMS 行为**（同一口塞两个框
   IoU < 默认 0.7，所以都留下），不是标签教出来的。**处置：推理侧按"每张 head 有无"计数**（集成方案即此）。
   去重规则仍保留 —— 它的价值是**标签卫生**（消掉自相矛盾的标注），不是涨点。
2. **"旋转增强提升 gag 召回"——两种子时成立、三种子后消失**（0° 0.60→三 seed 0.67；30° 0.68/0.66）。
   真正稳的只有"旋转补回侧躺/倒置的眼睛"：交付 eye 15.0 → 16.3。

**误报水平（上线前的关键数）**：544 张自动负样本（WD14 说没有 + 现役模型没报；287 张人判样本上这两个
信号说"没有"的准确率 gag 98.9% / 眼罩 98.0%）上，新模型 gag 误报 10 张（1.84%）、眼罩 14 张（2.57%）。
在**两边都没见过的 45 张 val** 上做 head 级对比：gag 打平（41/43 vs 42/43，均 0 误报）；
**眼罩 5/5 且 0 误报 vs 现役 5/5 但 3 误报（精度 0.62）** —— 这是"用单个四类权重替掉现役 face+gag 两模型并集"
的实证理由。
