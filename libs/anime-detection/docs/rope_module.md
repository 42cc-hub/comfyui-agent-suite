# 绳子模块（M4）— kernel 版预标注

**目标**：人只画粗标注（PS），产出一个像素级二分类模型，把整批图自动预标注成"重绘蒙版"。
单类（rope）、二值为主 + 软置信度；不做实例、不做上下压、不做 alpha。
**类别定义（2026-10-11 更新）**：正类 = 绳子，**不限颜色/材质**（红、白、棕、彩绳都算）；
负类 = 铁链/镣铐、绷带、布条、缎带、皮革束带、乳胶/胶衣、红衣物、长袜。
（早期标签按"只标红绳"做，白/棕绳被涂成负类 → 需要复盘重标。）

> 现状（2026-10-11）：结构选型已收敛（预训练骨干 + 薄解码器 + 语义分割），瓶颈在数据与工作点。
> 最新数字、误差归因与待决问题见 `docs/rope_network_review.md`（供外部评审）与
> `docs/rope_feedback_analysis.md`（对评审意见的逐条核对）；本文件下半部分保留早期实验记录。

## 接口（对外固定，改前先说）

```
python scripts/rope_predict.py --src <图片或目录> --out <目录> [--conf 0.565] [--backend auto]
```
产物三件套（`<name>` = 主名，空格→下划线）：
* `<out>/<name>_mask.png` 二值 0/255（重绘蒙版）
* `<out>/<name>_conf.png` 0~255 灰度置信度（直接当软蒙版，不用再羽化）
* `.runtime/rope_cv/overlay/<name>_overlay.png` 叠加图（红=mask、青=边界）；`--overlay-dir` 可改

**当前交付权重（2026-10-14 更新）**：`data/masks/rope/weights/rope_unet_resnet18_g14.pt`
（预训练 resnet18 骨干**不冻结** + RGB + ±20° 旋转，**79 张人工标注**训练，thr 0.90，tile 256）。
留出 s01~s05 同一口径对照上一版（30 图、thr 0.92）：

| 交付权重 | P | R | F1 | 笔数（误检块+漏检段） |
|---|---|---|---|---|
| 旧 `rope_unet_resnet18_full.pt` | 0.899 | 0.838 | 0.848 | 298（182+116） |
| 新 `rope_unet_resnet18_g14.pt` | 0.862 | **0.9812** | **0.9178** | 340（294+46） |

**读法（写死防误读）**：换权重买到的是**工作点平移**——漏检段 −60%、误检块 +62%、笔数 +14%，
不是"笔数下降"。三 seed（F1 0.9178 / 0.9211 / 0.9441，笔数 340 / 279 / 281）均值 F1 0.9277±0.0117、
笔数 300±28，与旧配置的 G3 基线**无差别**；选它的理由是"宁可略偏大、不要漏阴影段"。
交付的是 **seed 0**（预注册的第一个 seed，不按留出集挑）。依据：`docs/rope_runs_check_2026-10-13.md` §7、
`docs/rope_C_result.md` §2c。旧权重仍留在盘上，`--weights` 可指回去。
`rope_predict.py` 的默认权重自动选：有该文件（或旧 full）且有 torch 就用它，否则退回不依赖 torch 的 MLP 兜底
`rope_mlp_k9_4img.npz`（k=9 邻域 HSV → 48-24 → 1，12,913 参数）。`--conf` 可覆盖阈值。
权重字典里带 `in_mode`（hsv/rgb），推理会自动沿用训练时的输入表示。

其它脚本：`rope_train.py`（按整图留出训练+评测+导出）、`rope_eval.py`（P/R/F1 + 人工成本 KPI）、
`rope_unet.py`（U-Net 实验）、`rope_mask_to_label.py`（人标 mask → YOLO-seg/多边形）。

## 诚实的跨图评测（按整图 leave-one-image-out，测试集真实先验；`rope_eval.py` 统一口径）

4 张图（p01~p04）：

| 模型 | 参数量 | P | R | F1 | 预计笔数(误检块+漏检段) | 稠密耗时 |
|---|---|---|---|---|---|---|
| MLP k9 (48-24) | 12,913 | 0.564 | 0.740 | 0.640 | 347 (214+133) | numpy 8,620 / torch 857 ms/Mpx |
| U-Net base24 + 翻转/尺度/有界颜色增强 | ~470k | 0.570 | 0.911 | **0.701** | **211 (139+72)** | 161 ms/Mpx |

逐图 F1：MLP 0.748 / 0.558 / 0.427 / 0.634；U-Net 0.753 / 0.898 / 0.646 / 0.626。
U-Net 的召回（0.911 vs 0.740）和漏检段（72 vs 133）明显更好 → **用户提的"宏观走向"方向被验证**；
但精度都只有 0.57，误检集中在 p01/p04 的红色同色物。

3 张图时的参考（同口径）：MLP F1 0.625（预计笔数 284）；U-Net 无增强 F1 0.799（134）。

> ⚠️ 两个更正：① 交接时报的"跨图 bestF1 0.9381"是**评测泄漏**（用全部图训一个模型再逐图评），
> 已改为每 fold 只用其余图训练；② 一次"U-Net+增强 F1 0.459"的结论作废——当时 `crop()` 返回的是
> 通道优先数组，`a[:, ::-1]` 翻的是 **H/S/V 通道轴**，增强在毁数据而不是做增强。已修（保持 HWC，
> stack 后再 permute），并改成不会溢出的增强：亮度＝gamma、饱和度＝有界插值、色相 ±1.4 环形平移、
> 缩放 0.75~1.33；自检越界像素 0。

## 已知失败模式

* **跨风格泛化是当前瓶颈，不是架构**：3 张图配色/画风一变，就崩一边（U-Net 在 p03 过检到 10% 覆盖、
  在 p01 只召回 0.15）。加增强（翻转+HSV 抖动）反而把 p01 打崩 → 数据量不够是主因。
* **只学过红绳**：本批标注里白/灰束带、长袜、皮带都是负样本 → 模型不会把白绳当绳；要扩到白绳须改标注约定。
* **难负类确实会误检**：p02 有 701 px"像绳的红像素"（红绳 vs 红皮肤/红饰物），模型误判 557 px（79%）。
* **细/远绳易断**：极细段与低对比暗部会漏，表现为 mask 断续（MLP 漏检段 120 个 vs U-Net 54 个）。
* 单图内块棋盘留出（≈0.93）会高估，只能用来选结构，不能当交付指标。

## 2026-10-12 夜间自主实验（8 张标注图：p01~p05 + q03；q01/q02 为自动全负样本）

**新增硬技术 1 — clDice 拓扑损失**（[Shit et al. 2021](http://arxiv.org/pdf/2003.07311v5)）：细管状结构专用，
可微骨架算中心线 Dice，直接惩罚"断成好几段"。**两个坑**：① 必须用**各向异性可分离腐蚀**（3×1 与 1×3 取 min），
否则细线的开运算等于自身、skel≡0、损失恒为 1（等于白加）；② 迭代数要 ≥ 绳半宽（20px 宽实测需 iters≥12，
默认取 16），骨架提不出来时返回可微 0，避免给出与目标无关的乱梯度。
自检：相同输入 loss 0.000、断半段 0.108。

**新增硬技术 2 — 半监督一致性**（FixMatch/UniMatch 简化版，[CVPR23](https://ar5iv.labs.arxiv.org/html/2208.09910)）：
无标注图 → 弱视图（翻转+缩放）经 **EMA 教师**出伪标签（τ=0.9 双向）→ 监督强视图（旋转/模糊/有界颜色抖动），
带 ramp 预热。无标注池抽 `<你的图片目录>\_PIC0.._PIC4`（排除已标注图），补的是"同批画风但没标过"的多样性。

**增强（按用户意见重做，全部不越界，越界像素自检为 0）**：翻转 + 90° 旋转 + 尺度变焦 0.75~1.33 +
高斯模糊 σ∈0~2（p=0.3，在 BGR 里做再转回 HSV，避免红色 0/1 环绕处串色）+ 亮度 gamma / 饱和度有界插值 /
色相 ±1.4 环形。另加 **4 视图 TTA** 作为独立推理档。

**实验编排**：`.runtime/rope_cv/ps_work/autopilot.py`（独立进程，结果追加到 `autopilot_summary.md`）：
E0 纯 BCE 消融 → E1 +clDice → E2 +半监督 → E3 TTA 推理。注意：harness 的后台作业会随会话被回收，
长训练一律用 `Start-Process` 起独立进程。

**为什么不走 YOLO-seg**：我们的需求是**单类像素级二值**，而实例分割对交叉/缠绕的绳容易把一根拆成多个实例，
且细长带的 mask 精度是 YOLO 系公认弱项；语义分割 + 拓扑损失 + 半监督更对路。同源工作可借鉴
[DLO 弱监督半自动标注](https://github.com/lar-unibo/DLO-WSL)（可变形线状物体的骨架先验）。

### 夜间实验结果（8 张 LOO，同一 KPI 口径）

| 实验 | P | R | F1 | 预计笔数 | 误检块 | 漏检段 |
|---|---|---|---|---|---|---|
| MLP k9（局部 9px，交付兜底） | 0.756 | 0.822 | **0.787** | 432 | 285 | 147 |
| E0 U-Net 纯 BCE | 0.654 | 0.882 | 0.751 | **312** | 224 | 88 |
| E1 U-Net + clDice | 0.621 | 0.916 | 0.740 | 333 | 258 | **75** |

* **clDice 确实按设计生效**：漏检段 88 → 75（−15%），q03 召回 0.923 → 0.960，无绳图 q02 的误检 91,512 → 60,638 px。
  但也把误检块从 224 顶到 258，F1 净亏 0.011 → 建议把权重从 0.5 降到 ~0.25 或分两阶段用。
* **主 KPI（预计笔数）U-Net 更好**：312 vs MLP 432；但 F1 上 MLP 更高（0.787）——因为 MLP 的误检块小而密、
  U-Net 的块大而少，像素级 F1 与"人擦几笔"这两个指标并不一致，按用户"人工成本优先"的口径应以笔数为准。
* **重要否证（对后处理思路）**：我验了两个"用形状救"的假设，都不成立——
  ① 误检块 vs 真绳块的形态**完全重叠**（最大内切直径 p50：FP 10.4 vs TP 22.8，面积 p50：245 vs 2163，
  误检反而更小更细）；② 误检块基本都**贴着**预测的绳网（离最近大块的距离 0 个块 >10px）。
  ⇒ 剩下的错是**语义错**（细的红缎带/红布料边/潮红），局部形状与连通性都救不了；
  唯一有效的是补这一类外观的**负样本标注**，或用半监督把决策边界收紧。
* 全负样本图（q01/q02）单列报误检量、不计入 F1：这类图是最好的"精度探针"，建议以后多标几张（不用画绳，全蓝即可）。

## 下一步

1. 继续标剩余图（q04/q05 等）→ 每加一图重跑 `rope_eval.py`，把"预计笔数"写回本文件（主 KPI）。
2. 看 E2（半监督）/E3（TTA）结果：若半监督把 fold 波动压到 <0.15 F1 且笔数下降，U-Net 转交付（权重 `.pt`）。
3. clDice 权重降到 0.25 再测一轮；或只在训练后 1/3 阶段启用（先学颜色/形状，再修拓扑）。
4. 优先补**难负类**标注：红缎带、红布料、红色潮红、黑亮皮革（q01 那种）——实验证明这比任何后处理都值。
5. 后处理只保留"去极小碎块"；骨架桥接仅在 `--conf` 偏低的工作点上用。
